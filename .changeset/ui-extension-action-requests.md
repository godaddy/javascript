A `dom-bundle` UI extension can ask its host to run an action. The mount input now carries an optional `requestAction({ action, input })`, which resolves with the host's result. Hosts handle requests with a new optional `onActionRequest` prop on `Target` and `UiExtensionRuntimeHost`, or through the runtime's existing `onActionRequest` mount option, which now also receives an optional second argument. The handler gets a structured clone of the request and the metadata of the extension that sent it, built from the host's own record, and the extension gets a structured clone of the result. Without a handler, when the host rejects, when a value can't be cloned, without an action name (or with one that is blank or has spaces around it), or when the extension unmounts (including while a request is still waiting on the host), the request rejects with an `action_rejected` runtime error; the host's own reason isn't passed to the extension. The function stays the same for the life of the mount, and under `Target` and `UiExtensionRuntimeHost` it always reaches the host's current committed handler. A request rejected at unmount may still have run on the host. A runtime mounted again before its earlier mount finishes now unmounts the replaced bundle, and that bundle's requests are refused. Existing bundles and hosts work unchanged.

Hosts that pick a target's extensions before rendering can call the new `getEnabledStoreUiExtensions({ storeId, target, apiHost })`, the same discovery request `useEnabledStoreUiExtensions` sends, outside React.
